# 演習: 結合律を確かめる

書籍『Category Theory for Programmers』第1章の challenge を題材にした演習です。

**問題**: 次のHaskellの関数 `f`、`g`、`h` を定義し、`h . (g . f)` と `(h . g) . f` が実際に同じ関数であることを確認してください。

```haskell
f :: Int -> Int
f x = x + 1

g :: Int -> Int
g x = x * 2

h :: Int -> String
h x = "value: " ++ show x
```

**解答方針**: どちらの式も、`f` で1を足し、`g` で2倍し、`h` で文字列化する、という同じ変換の連なりになるはずです。実際に `x = 3` を入れて手計算すると、両方とも `"value: 8"` になることが分かります。

これは単なる偶然ではなく、[[結合律]] という [[圏]] の法則そのものです。関数を「どこで区切って合成するか」は、最終的な振る舞いに一切影響しません。パイプライン処理を設計するときに「途中の関数をどうグルーピングしても結果は変わらない」と安心できるのは、この法則のおかげです。
